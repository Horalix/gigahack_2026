# Local meeting service

Run from the repository root with Python 3.11 and FFmpeg/FFprobe on `PATH`. Create a dedicated virtual environment outside the OneDrive checkout, then install the pinned environment with its Python: `python -m pip install -r services/meeting/requirements.lock`. The system Python already has unrelated package conflicts, so use the isolated environment for a repeatable run. Runtime models are prepared separately by PBI-003 and must be local before transcription starts.

Start `python -m uvicorn services.meeting.api:app --host 127.0.0.1 --port 8000` and `python -m services.meeting.jobs` in separate terminals, then run `npm run tauri -- dev` (or `npm run dev` to use the browser UI). The first user creates the installation's administrator from the sign-in screen; later accounts are provisioned through `/api/users`. The service accepts loopback connections and allowlisted app origins only; mutating requests require a trusted origin. Sign in to receive an HttpOnly, SameSite session cookie. Administrators can provision accounts, but administrator status does not grant access to meeting content. Meeting owners must explicitly grant viewer/editor access. There is no shared default password or demo-principal bypass.

`MOM_DATA_DIR` optionally selects a directory outside Git and OneDrive. By default the database and recordings use the OS local application-data folder. The source upload stays intact; an audio-only, mono 16 kHz WAV derivative is created for ASR. Audio/video media are probed by FFprobe and decoded by FFmpeg. The source filename is ignored. If a file has multiple audio tracks, pass its FFprobe stream index as `audio_track_index` when uploading.

The API stores jobs; it does not run inference inside the request. The worker claims one job transactionally, renews a lease, and resumes expired claims after a process stops. The transcription checkpoint is written and synced before committing transcript rows. A `ready` job means local ASR and evidence-backed decision extraction both completed; the meeting remains `transcript_ready` until document generation/review states are added. Decision candidates are always marked for human review and are returned from `GET /api/meetings/{id}` with timestamped quote evidence. No mail implementation is present. The local llama.cpp adapter starts one loopback-only server per job and reuses it for bounded extraction after ASR; Qwen thinking output is disabled. It expects the pinned CPU runtime under `%LOCALAPPDATA%\SecureMOM\runtimes\llama-b11200-cpu` by default; `MOM_LLM_SERVER_EXECUTABLE` can point to another locally provisioned build.

Current HTTP routes: `POST /api/auth/setup` (only before the first account), `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`, admin-only `GET/POST /api/users` and `PATCH /api/users/{id}`, `GET /api/health`, `GET /api/profiles`, authenticated `GET/POST /api/patients`, `GET/PATCH /api/patients/{id}`, explicit `POST/DELETE /api/patients/{id}/meetings/{meeting_id}` links, `GET /api/meetings` (search/pagination), `POST /api/meetings`, `GET /api/meetings/{id}`, `PUT /api/meetings/{id}/segments/{segment_id}` (revision-checked correction), owner-managed `GET/POST/DELETE /api/meetings/{id}/grants`, `POST /api/meetings/{id}/audio`, `POST /api/meetings/{id}/jobs`, `GET /api/jobs/{id}`, and `POST /api/jobs/{id}/retry`. Patient listing uses keyset pagination (25 default, 100 max) and limits records/counts to those created by the caller or reachable through a linked meeting grant. Patient records store only display name, optional hospital reference and status. A patient link never grants access to its meeting; meeting permissions are checked independently. Meeting/job writes require owner/editor. The [versioned record contract](../../contracts/README.md) defines meeting payload meanings. A new job accepts `profileId`, `asrModelAlias`, and `llmModelAlias`; its resolved choices are frozen in `modelConfig`. Profile listing shows model file presence and local GPU compatibility; job start verifies both selected ASR and LLM asset digests. API errors use safe codes and request IDs; they do not echo audio or transcript text.

The workbench supports uploaded audio/video and browser microphone recording. A recording is sent only when the user starts processing. The profile selector exposes the laptop8 and hospital16 presets only when the host has enough detected VRAM; model aliases and `MOM_ASR_LANGUAGE` can be overridden through local environment configuration. Romanian is the default selection and is pinned into the job configuration; `auto`, Russian and English are also selectable. ASR and LLM run serially in the worker so their model memory can be released between stages. This limits overlap; it does not guarantee every recording/model combination stays within hardware limits.

This is a single-installation local access boundary, not hospital SSO or a multi-tenant deployment. Source-media download/range and export routes are not implemented yet; any such route must apply the same object permission check before it is added. Use the bootstrap CLI only on an installation with no accounts.

The explicit limits are 2 GiB upload size, six hours media duration, tested FFmpeg containers/codecs and a bounded decoder process timeout. Unsupported, corrupt, missing-audio and ambiguous multi-track files produce visible errors. These limits are implementation bounds, not a claim that every possible video can be decoded safely on every machine.

If FFmpeg recovers audio despite damaged frames, the asset includes `decodeWarning`. The source stays intact so a reviewer can check for missing speech.
