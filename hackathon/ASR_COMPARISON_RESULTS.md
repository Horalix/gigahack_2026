# ASR comparison — Romanian Medpark sample

**Recommendation: keep Whisper large-v3 as the app ASR. Do not switch to OmniASR for the demo.** On the same saved 11m43s WAV and Microsoft-generated reference, Romanian-forced Whisper had the lowest text disagreement. Omni CTC was much faster but substantially worse; Omni LLM was also worse and missed the one-hour speed target.

The batch-2 laptop Whisper score is 15.3 percentage points lower WER than the language-conditioned Omni LLM, and 21.0 points lower than Omni CTC. The historical `int8_float16` Whisper run scored 3.9 points better than the previous batch-1 FP16 profile, but that precision failed a real 60-second inference smoke on the pinned local CUDA stack; both laptop settings therefore use FP16. The controlled WSL Whisper-window run was stopped after more than 12 minutes without completing; its timing is not reported as a completed run. Timings are descriptive, not a strict speed ranking: Whisper ran natively on Windows; Omni ran under WSL, and windowing differed. All completed candidates used the same audio and saved Romanian reference with the same scoring normalizer.

The beam-1 probe used the same WAV and reference as the previous batch-1 beam-5 baseline; it was 10.6s slower and 7.9 percentage points worse in WER. Keep beam 5. The batch-2 probe used that frozen input in two runs (46.708s and 46.632s), with identical scores. WER is effectively unchanged from batch 1, CER rises by about 2 percentage points, and measured peak device use was lower. The laptop profile now uses batch 2: on this sample it was 2.54× faster with similar WER. This is a strong single-sample throughput result, not hour-long or multilingual qualification; watch critical medical spellings during review.

## How to read this

- These are **WER/CER disagreement scores against an unverified Microsoft machine transcript**, not measured clinical accuracy. The provided share page could not be independently retrieved during this run; the saved transcript was used as supplied. A fluent Romanian reviewer should verify clinical terms, negation, doses, names, and code-switches before making accuracy claims.
- The current app `laptop8` upload-to-worker run completed ASR and local decision extraction on the 11m42.5s sample: 166 transcript segments and 35 evidence-linked items requiring human review. Current ASR wall time was 118.6s. Its one-hour ASR-only extrapolation is 10.1 minutes, leaving about 4.9 minutes for decode, decision extraction, review, and artifact creation. The complete app workflow has not been timed on a one-hour recording, so the 15-minute end-to-end target is unverified.
- A later run on the original 702.635s M4A used forced-Romanian FP16 and produced 191 segments in 138.676s. Its first LLM pass failed because the verbose final response exceeded the output limit. After switching reconciliation to select source-validated event indexes (the service reconstructs exact text/evidence), a checkpoint retry completed in 95.68s with 20 decisions, all requiring human review. The measured ASR + successful LLM stage sum is **234.4s**, a linear **20.0 min/hour projection**. With batch 2, the same ASR adapter completed the 702.549s WAV in 46.7s (two identical runs), while 95.68s is the latest measured LLM stage. Their provisional stage-sum projection is **12.2 min/hour**, but this is not a complete one-hour run or a cold upload-to-approved-file timing. A separate 6,000-byte experimental batch took 121.21s and returned 31 review items; it did not improve speed, so production remains at 3,200 bytes.
- Current integrated `laptop8` batch-2 path: the same 702.635s M4A, Romanian selected, passed through the real upload/decode API and `run_once` worker in an isolated temporary data directory and reached `ready`. Upload/decode took 1.42s, ASR 44.84s, decision extraction 70.20s, and upload-to-ready 123.04s (28 transcript segments; two extracted decision items). This is 10.5 min/hour by linear upload-to-ready projection, including model load and local decision extraction. It supersedes the earlier 20.0/12.2-minute estimates for this current profile on this sample, but is not a one-hour or email-receipt test. RAM was 8.7 GiB free before job admission and a spot check during LLM work observed 4.2 GiB free; no out-of-memory failure occurred. ASR reported 4,603 MiB device-wide peak; GPU usage returned to 0 MiB after the run. LLM peak GPU use was not sampled.
- 2026-09-27 follow-up: the same 702.635s Romanian M4A reached `ready` with `MOM_LLM_CONTEXT_SIZE=4096` and `MOM_LLM_MAX_OUTPUT_TOKENS=2048`: upload/decode 1.77s, worker 133.41s, total 140.93s, 28 transcript segments, three evidence-linked items, 4,694 MiB peak device-wide GPU use, and 6.75 GiB minimum free RAM. Linear projection is 12.1 min/hour; this is a single 11m43 sample, not an hour qualification. The 8,192-token profile remains the default. A separate repeated-clip hour stress diagnostic failed context fitting before the compact-prompt update; it is excluded from acceptance and quality evidence because it is not genuine one-hour speech.
- An automated browser journey then uploaded the actual M4A through the app, recovered from an unsupported LLM evidence candidate using the saved checkpoint, displayed 182 transcript passages and 18 review-required decisions, and generated/downloaded the HTML file after exercising the approval checkbox. The checkbox was automated; this does not represent clinician review or alter the ASR comparison scores.
- Romanian forcing matters: the historical Auto run selected Russian and scored 81.8% WER under this normalizer, while forcing Romanian in the app gave 47.9%. Keep the explicit language selector and select Romanian when known.
- Omni CTC has no forced-language input in the tested standard pipeline; Omni LLM accepts the Romanian code but has poor measured agreement and higher VRAM. Neither is a drop-in app backend today: the app adapter supports faster-whisper and word-level timestamps; Omni returned untimed window text.
- VRAM is the peak device-wide `nvidia-smi` reading, not process-attributed memory. The current Whisper value includes other processes; it is not attributable to Notavra alone. Omni LLM completed on the 8 GB laptop GPU, but its 5,603 MiB is also device-wide. No RTX 5080/16 GB run was made because that host was not accessible from this checkout. The 16 GB profile and CUDA 13 runtime remain unverified.
- First Omni LLM setup also downloaded about 8.49 GB of weights. Its first 30s smoke took 807.8s wall including the cache miss; the full cached run reported 132.6s load plus 136.0s inference. Do not include model download in the advertised processing time; provision and verify model files before offline demo.

## Decision and next work

Use Whisper large-v3 for the demo, with Romanian explicitly selected for Romanian-only input. The measured 8 GB laptop profile is FP16, batch 2, beam 5; do not use historical `int8_float16` until it passes inference on the pinned CUDA runtime. The 16 GB profile remains batch 4 and is not yet host-tested. Keep Auto available for unknown language, but make Romanian the contest default. Do not switch to either tested OmniASR model: both had substantially higher disagreement on this sample, and the Omni LLM also misses the ASR speed budget. Revisit only with Romanian medical adaptation and the same frozen human-reviewed test set.

Before claiming medical transcription quality, have a fluent reviewer annotate a consented reference and critical medical terms. Before claiming the 15-minute end-to-end gate, time the complete one-hour workflow with LLM extraction and artifact delivery. Repeat the benchmark on the 16 GB workstation when available. This report is a single-recording model-selection result, not a production validation.
